# DB2 stores (client data + hotfixes)

The DB2 structs are in `crates/azothacore-server/src/shared/data_stores/db2_structure/wow7_3_5_26972.rs`
(`#[derive(WDC1, sqlx::FromRow)]`). Each struct is read from the client `.db2` file in `DataDir/dbc/<locale>/`,
then the matching `azcore_hotfixes` table is layered on top. The SELECT is generated by
`wow-db2-proc-macros`: a field `foo_bar: [T; N]` reads columns `FooBar1..FooBarN`, and `LocalisedString` fields
read `<col>` plus `<table>_locale.<col>_lang`.

## Field types: two sources must agree

- **The file layout** (field order, width, array size) comes from **WoWDBDefs**
  (`https://github.com/wowdev/WoWDBDefs`).
  - Pick the `LAYOUT` block whose hash equals the struct's `#[layout_hash]` and whose `BUILD` list includes
    `7.3.5.26972`.
  - TC 7.3.5's own `DB2Structure.h` has known errors: `SpellAuraOptions.ProcTypeMask` is `[2]`, and
    `WMOAreaTable.NameSetID` is `u16`.
- **Signedness must match the hotfix SQL column exactly.** sqlx decodes strictly: `u32` only reads `INT UNSIGNED`,
  and `i32` only reads `INT`. A mismatch fails the whole store, which aborts startup (and then the vmap init reports
  missing `ChildMapData` / `ParentMapData`).
  - Mismatches stay hidden while the hotfix table is empty, because no rows means nothing is decoded.
  - Follow WoWDBDefs signedness when the SQL column agrees.
  - Where the TC 7.3.5 column disagrees with WoWDBDefs (mostly class masks and flags, plus every `ID`), keep the SQL
    type, with a `/// WoWDBDefs 7.3.5.26972: …; kept to match the TC 7.3.5 hotfix column` comment.
- **Strings** decode into `String`, so hotfix text columns must not be NULL. TC reads NULL as `''`; store `''`.

## Checking

After editing a struct or the hotfix schema, compare every struct against WoWDBDefs (by layout hash + build) and
against the hotfix schema: width/array, sign vs WoWDBDefs, sign vs SQL, and WoWDBDefs vs SQL. A local checker script
does this; it is not in the repo. The real test is a worldserver start with populated hotfix tables, which must
log `>> Initialized 233 DB2 data stores`.
